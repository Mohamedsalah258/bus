# BSU Bus — Backend foundation

باك إند أولي لمنظومة النقل الجامعي باستخدام **Node.js 24، NestJS، TypeScript وPostgreSQL**.

هذه أول مرحلة تنفيذ، وليست نسخة إنتاج مكتملة. لا يوجد اتصال بالموقع القديم أو ببيانات الجامعة الحقيقية.

## المنفذ

- تسجيل حساب مستفيد، دخول JWT لمدة 15 دقيقة مع Refresh token يُستخدم مرة واحدة ويتجدد، وخروج يلغي كل الجلسات. حد محاولات فاشلة لكل بريد مشترك بين النسخ.
- 7 أدوار بمصفوفة صلاحيات واحدة (`modules/auth/permissions.ts`) تُراجع من قاعدة البيانات في كل طلب، ومنسق الكلية محصور في كليته.
- فئات المستفيدين بيانات يحددها الأدمن، وكل خط يحدد الفئات المسموح لها بالاشتراك.
- إدارة المستخدمين للأدمن: إنشاء بكلمة مرور مؤقتة، تغيير الدور، التعطيل، إعادة ضبط كلمة المرور وMFA، وكل ذلك مسجل بسبب.
- مصادقة ثنائية TOTP إلزامية للأدمن والـ Dispatcher، مع 10 رموز استرداد.
- دخول المستفيدين برمز على البريد بدون كلمة مرور، وفورم اشتراك موحد مطابق للموقع القديم (بدون الرقم القومي).
- تأكيد البريد برمز OTP، واستعادة كلمة المرور برمز على البريد (القرار D3). البريد هو قناة الإشعار الوحيدة (D6)، عبر outbox بإعادة محاولة.
- خطط اشتراك سنوية أو فصلية، مجانية أو مدفوعة (D2)، ودورة حياة كاملة للاشتراك: استكمال، سحب، إيقاف، وإعادة تقديم. الدفع يُسجل يدويًا، والحجز يُفتح بعد السداد الكامل.
- كليات، مواسم، خطوط ومحطات مرتبة، مركبات وسائقون.
- طلب اشتراك ومراجعة إدارية بقرار مسبب؛ الاشتراك لا يحجز مقعدًا تلقائيًا.
- إنشاء رحلات محددة بالتاريخ والسعة؛ منع تداخل تخصيص السيارة أو السائق.
- حجز وإلغاء وبيانات حجوزات المستخدم فقط، مع التحقق من أهلية الاشتراك بتاريخ الرحلة.
- معاملات وأقفال PostgreSQL لمنع تجاوز السعة والحجز المكرر، ومفتاح لمنع تكرار نفس الطلب عند إعادة الإرسال.
- سجل تدقيق للأحداث الرئيسية، تحقق مدخلات، رسائل خطأ عامة، حدود طلبات، Swagger وCI.

## بنية المشروع

Modular monolith مقسم إلى وحدات: `auth`، `users`، `audit`، `faculties`، `seasons`، `routes`، `fleet`، `subscriptions`، `trips`، `bookings`، كل منها Controller → Service → Repository. الشجرة الكاملة واتجاه الاعتماد وبروتوكول الأقفال واصطلاحات الكود في [Architecture](docs/ARCHITECTURE.md). اقرأه قبل إضافة أي وحدة.

## تشغيل محلي

يلزم Node.js 24 وPostgreSQL 17، أو Docker لتشغيل قاعدة البيانات فقط.

```bash
npm ci
cp .env.example .env
docker compose up -d db mail   # PostgreSQL + Mailpit (صندوق بريد محلي على http://localhost:8025)
```

على PowerShell استخدم `Copy-Item .env.example .env`. غيّر `JWT_SECRET` بقيمة عشوائية طويلة، واضبط `MFA_ENCRYPTION_KEY` (32 بايت base64، الأمر موجود في المثال؛ تغييره لاحقًا يُبطل كل تطبيقات المصادقة المسجلة)، واضبط `DATABASE_URL` و`POSTGRES_PASSWORD` ليستخدما كلمة مرور متطابقة. القيم المحلية في المثال ليست للإنتاج.

توليد مفتاح محلي:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
docker compose up -d db
npm run build
npm run db:migrate
```

اضبط `BOOTSTRAP_ADMIN_EMAIL / BOOTSTRAP_ADMIN_NAME / BOOTSTRAP_ADMIN_PASSWORD` داخل `.env`، ثم:

```bash
npm run admin:create
npm start
```

احذف كلمة مرور إنشاء المسؤول من `.env` بعد نجاح الإنشاء. الأمر ينشئ حسابًا جديدًا فقط؛ لا يرفع صلاحيات حساب موجود تلقائيًا. لا توجد كلمات مرور افتراضية أو بيانات جامعة مزروعة.

- API: `http://localhost:3000/api/v1`
- Swagger: `http://localhost:3000/docs` عند تفعيل `SWAGGER_ENABLED=true` في التطوير.
- فحص التشغيل: `/api/v1/health/live`؛ جاهزية قاعدة البيانات: `/api/v1/health/ready`.
- للتطوير: شغّل `npm run build:watch` في طرفية و`npm run start:dev` في أخرى بعد أول بناء.
- `npm run openapi:export` يحدث [عقد OpenAPI](docs/openapi.json) دون الاتصال بقاعدة بيانات أو تشغيل خادم HTTP.

## أول تجربة

1. دخول المسؤول من `POST /auth/login`، ثم تسجيل المصادقة الثنائية: `POST /auth/mfa/setup` (امسح `otpauthUrl` بتطبيق مثل Google Authenticator)، ثم `POST /auth/mfa/activate` بالرمز. احفظ رموز الاسترداد. بعدها ادخل من جديد: `login` يرجع `mfaToken`، وترسله مع الرمز إلى `POST /auth/mfa/verify`. استخدم الـ accessToken مع زر **Authorize** في Swagger.
2. إنشاء كلية وفئة مستفيد على الأقل (`POST /categories`)، ثم موسم، وخط بمحطتين أو أكثر والفئات المسموح لها، وسيارة وسائق، ثم رحلة مستقبلية.
3. إنشاء خطة اشتراك للموسم (`POST /plans`: سنوية أو فصلية، والرسوم بالقرش؛ 0 = مجاني).
4. المستفيد يدخل ببريده بدون كلمة مرور: `POST /auth/code/request` ثم `POST /auth/code/verify` بالرمز (في التطوير يظهر في Mailpit)، ثم يملأ فورم الاشتراك الموحد `POST /subscriptions/apply`: الاسم، الهاتف، الوظيفة، الكلية، الفئة، الخطة، وخط السير.
   للجدولة المتكررة: `POST /schedules` (الوقت، الأيام بدءًا من السبت، المقاعد، مواعيد الغلق)، ثم `POST /schedules/{id}/generate` لإنشاء رحلات فترة كاملة، والإجازات من `POST /service-exceptions`.
   لتحميل خطوط الموقع القديم الخمسة بمحطاتها وسياراتها وسائقيها: `npm run seed:legacy-routes` (البيانات في `data/legacy-routes.json`).
5. مراجعة الطلب عبر `PATCH /subscriptions/{id}/review` (موافقة، رفض، أو طلب استكمال). للخطة المدفوعة: تسجيل الدفع `POST /subscriptions/{id}/payments`.
6. المستفيد يرسل `POST /bookings` ثم يستعرض `GET /bookings/mine` أو يلغي الحجز.

تفاصيل الطلبات والأخطاء في [API walkthrough](docs/API.md)، والقرارات والحدود في [Implementation scope](docs/SCOPE.md).

## الاختبارات

```bash
npm run check        # typecheck + lint + format + unit + e2e
npm run test:unit    # منطق نقي فقط
npm run test:e2e     # دورة HTTP كاملة
```

تشمل اختبارات HTTP محلية على PostgreSQL مضمّن (PGlite): الصلاحيات، الدورة كاملة، السعة، الإلغاء، عزل المستخدمين وتكرار الطلبات. هذا الاختبار **تتابعي** ولا يثبت تنافس الاتصالات المستقلة.

اختبار التزامن يستخدم PostgreSQL مستقلًا؛ يشغله GitHub Actions تلقائيًا بعد رفع الكود:

```bash
# Set TEST_DATABASE_URL to an ISOLATED database named bus_test.
npm run test:integration
```

**الاختبار يفرغ جداول قاعدة الاختبار.** يرفض أسماء قواعد لا تنتهي بـ`_test`. عند عدم ضبط المتغير تظهر الحالة `skipped`، ولا تعتبر نجاح تحقق التزامن. لا تستخدم بيانات حقيقية في هذه القاعدة.

## النشر

- البناء بواسطة `Dockerfile`؛ العملية تعمل بمستخدم غير root.
- تطبيق الترحيلات خطوة نشر مستقلة: `node dist/scripts/migrate.js`. لا تطبق تلقائيًا عند كل تشغيل.
- إعداد `NODE_ENV=production` و`SWAGGER_ENABLED=false` وCORS لمصادر محددة، مع TLS ونسخ احتياطي وأسرار خارج المستودع.
- ملف Compose لقاعدة تطوير محلية فقط. ليس مخطط نشر إنتاج أو ضمان توافر.
- لا توجد إعدادات `trust proxy` تلقائية؛ تضبط فقط بعد معرفة عدد البروكسيات الموثوقة، لحماية حدود الطلبات من تزوير عناوين IP.
